# Data dictionary — the Day-0 world

All data is **fictional**, generated by `backend/scripts/generate_data.py` (seed 42; identical every run; `python tasks.py seed`).
It describes the world on **Day 0 = Thu 1 Oct 2026**, the day the Festive Scheme goes live and the nudge + survey is sent.
Everything after Day 0 (replies, flags, next best actions, participation, October sales, personas) is produced by the **loop
simulator** at runtime — see `docs/SIMULATION_SPEC.md` §5.

Money is in **₹ lakh** (`_l` columns): 100 L = ₹1 Cr. Indian FY: FY2026-27 = Apr 2026–Mar 2027.

## The five CSVs (`backend/data/csv/`) — what people read

| File | One row per | What's in it |
|---|---|---|
| `distributors.csv` | distributor (1,104) | Zone, territory, ASM · name, owner, town, class A/B/C, language on file, reply window · Day-0 features (secondary FYTD and last year, YoY, QoQ, down-month streak, SKUs billed, focus share, days since last invoice, schemes joined / qualified, OTIF) · **business potential** (town Emami potential, outlets covered, coverage share, potential, current monthly sales, headroom) · **four pillar scores + performance score** · **cohort** + reasons · Festive target, stretch, baseline forecast, predicted sales if participating |
| `monthly_performance.csv` | distributor × month (Apr 2025–Sep 2026) | Primary and secondary sales, unique SKUs and focus SKUs billed, focus revenue and share, invoices · **retailer orders, OTIF %, fill rate %, average delivery days** (delivery to retailers) |
| `schemes.csv` | distributor × scheme (last 3) | Scheme id, name, type, dates, rules · participated, progress vs target, **qualified** (hit the target) |
| `market_potential.csv` | town × category (118 towns × 5) | Population, households, retail outlets, penetration, monthly spend per household, **modelled TAM**, Emami fair share, **Emami potential** — synthetic, modelled (households × penetration × spend × fair share), not census data |
| `sim_traits.csv` | distributor | **Hidden** simulator truth (true language, reply habits, understanding, join probabilities, anchor scripts). Never shown in the app or sent to the LLM. |

The app reads the same data from `backend/data/emami_dx.sqlite` (tidy tables: `zones`, `territories`, `asms`, `distributors`,
`skus`, `billing_monthly` (incl. delivery columns), `schemes`, `scheme_history`, `scheme_targets`, `distributor_features`,
`cohort_assignments`, `sim_traits`, `markets`). `summary.json` holds headline numbers.

## Cohorts (rules v4.0, `backend/app/rules/cohorts.yaml`)

A 2×2 of **business potential** (the distributor's geography) vs **distributor performance**:

| | High performance (score ≥ 50) | Low performance |
|---|---|---|
| **High potential** (≥ ₹4.5 L/month) | Invest / Expand | Replace / Reassess |
| **Low potential** | Protect | Exit / Watchlist |

- **Business potential** = town's Emami potential (Σ categories of modelled TAM × fair share) × the distributor's share of the town's outlets.
- **Performance score** = 25% each of four pillar scores (0–100):
  - growth — YoY vs the FMCG market (+3.0%, NielsenIQ India Q1 2026): 50 = with the market, +10 pts ahead = 100;
  - schemes — qualified in N of the last 3 schemes;
  - focus — focus-product share vs 35%;
  - delivery — OTIF Jul–Sep, 70% = 0, 95% = 100.
- Weights, thresholds and targets are editable on the Cohort rules page (applied from the next cycle).
