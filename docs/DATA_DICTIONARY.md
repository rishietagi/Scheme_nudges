# Data dictionary — the Day-0 world

All data is **fictional**, generated by `backend/scripts/generate_data.py` (seed 42; identical every run).
It describes the world on **Day 0 = Thu 1 Oct 2026**, the day the Festive Scheme goes live and the nudge + survey is sent.
Everything after Day 0 (replies, flags, CTAs, enrolments, October sales, personas) is produced by the **loop simulator**
at runtime — see `docs/SIMULATION_SPEC.md` §5 for those run tables.

Money is in **₹ lakh** (`_l` columns): 100 L = ₹1 Cr. Indian FY: FY2026-27 = Apr 2026–Mar 2027.

| Output | What |
|---|---|
| `backend/data/emami_dx.sqlite` | The 12 tables below |
| `backend/data/csv/*.csv` | Same tables as CSV |
| `backend/data/summary.json` | Day-0 headline metrics, anchor facts, simulator expectations |
| `backend/tests/test_generated_data.py` | 9 checks that recompute the headline numbers from raw tables and re-apply the cohort rules |
| `backend/app/rules/*.yaml` | Cohort rules, survey, sanity checks, CTA catalogue (config the app reads) |

## The 12 tables, in 4 groups

### 1. Distributor data — what Emami's systems would provide
| Table | Rows | Columns | Emami field |
|---|---|---|---|
| `zones` | 3 | zone_id, name, state | Hierarchy (gap we added) |
| `territories` | 14 | territory_id (TER-01 = Kolkata North), name, zone_id, asm_id, distributor_count | Hierarchy |
| `asms` | 14 | asm_id (ASM-01 = Rahul Sen), name, territory_id, email | Hierarchy |
| `distributors` | 1,104 | distributor_id, name, owner_name, town, territory_id, asm_id, partner_since, **preferred_language (on file)**, reply_window, phone_masked, channel, classification (A/B/C) | 2. Classification |
| `skus` | 120 | sku_id, name (generic), category, pack, is_active (112), is_focus (20), case_size, ptd_price_per_case | 3. Active & focus SKUs |
| `billing_monthly` | 19,872 | distributor_id, month (Apr 2025–Sep 2026), primary_value_l, secondary_value_l, unique_skus_billed, focus_skus_billed, focus_revenue_l, focus_revenue_share, invoice_count | 1, 4, 5 |
| `schemes` | 4 | scheme_id, name, type, start_date, end_date, rules_text, status, is_current. Current: **SCH-2627-FES Festive Scheme · Oct 2026** | 6. Scheme details |
| `scheme_history` | 3,312 | distributor_id, scheme_id (last 3 schemes), enrolled, progress_pct, achieved | 6. Participation |

### 2. Scheme plan — targets and the prediction Day 30 is judged against
| Table | Rows | Columns |
|---|---|---|
| `scheme_targets` | 1,104 | distributor_id, scheme_id, **baseline_forecast_l** (October sales if they don't join), target_l, stretch_target_l (+25%), expected_uplift_pct, **predicted_sales_if_enrolled_l** |

"Hit the predicted sales boost" on Day 30 = actual October sales ≥ `predicted_sales_if_enrolled_l`.

### 3. Business logic — computed by our engine (pre-computed here for speed; the app can recompute)
| Table | Rows | Columns |
|---|---|---|
| `distributor_features` | 1,104 | As of Day 0: FYTD and last-year secondary, yoy/qoq growth, consecutive_down_months, unique_skus_sep, sku_range_delta_qoq, focus_share_q2, last_invoice_date, days_since_last_invoice, past_schemes_joined, joined_last_scheme |
| `cohort_assignments` | 1,104 | distributor_id, as_of, rule_version (v2.0), cohort, reasons |

### 4. Simulator only — HIDDEN
| Table | Rows | Columns |
|---|---|---|
| `sim_traits` | 1,104 | true_language, active_window, response_prob, median_response_hours, understanding, wants_asm_prob, enrol_prob_day0, enrol_prob_after_matching_cta, low_effort_prob, hit_prediction_prob, scripted_intent, scripted_response_hours, scripted_survey_seconds, scripted_flags, scripted_enrol_day, scripted_note |

**Never** return these through the API, show them in the UI, or send them to the LLM. They are the "hidden truth" the
simulator uses so the app can *learn* preferences from behaviour (e.g. Annapurna is on file as English but `true_language`
is Bengali — the persona discovers that when she asks for Bengali).
